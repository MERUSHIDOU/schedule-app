# エージェント・スキル編成

## 利用可能なエージェント（Task tool）

Taskツールのサブエージェントとして利用可能：

| エージェント | 目的 | 使用時機 |
|-----------|------|---------|
| planner | 実装計画 | 複雑な機能、リファクタリング |
| architect | システム設計 | 建築的な決定 |
| tdd-guide | テスト駆動開発 | 新機能、バグ修正 |
| security-reviewer | セキュリティ分析 | セキュリティ関連の変更 |
| build-error-resolver | ビルドエラー修正 | ビルド失敗時 |
| e2e-runner | E2Eテスト | 重要なユーザーフロー |
| Explore | コードベース探索 | 高速な検索・分析 |

## 利用可能なスキル（Skill tool）

スキルツール経由で呼び出し可能（`/スキル名`で実行）：

| スキル | 目的 | 使用時機 |
|--------|------|---------|
| plan (`/plan`) | 実装計画策定 | 複雑な機能、リファクタリング |
| tdd (`/tdd`) | TDDワークフロー | 新機能、バグ修正 |
| code-review (`/code-review`) | コードレビュー | コード作成後 |
| security-review (`/security-review`) | セキュリティレビュー | コミット前 |
| build-fix (`/build-fix`) | ビルド修正 | ビルド失敗時 |
| e2e (`/e2e`) | E2Eテスト | 重要なユーザーフロー |

## 即座のエージェント・スキル使用

ユーザープロンプト不要：
1. 複雑な機能リクエスト - **planner** エージェントまたは`/plan`スキルを使用
2. コード作成/修正直後 - `/code-review`スキルを使用
3. バグ修正または新機能 - **tdd-guide** エージェントまたは`/tdd`スキルを使用
4. 建築的な決定 - **architect** エージェントを使用

## 並列タスク実行

独立した操作には常に並列タスク実行を使用：

```markdown
# 良い例：並列実行
3つのエージェントを並列起動：
1. エージェント1: auth.tsのセキュリティ分析
2. エージェント2: キャッシュシステムのパフォーマンスレビュー
3. エージェント3: utils.tsの型チェック

# 悪い例：不要な場合の順序実行
最初にエージェント1、次にエージェント2、その後にエージェント3
```

## 複数視点分析

複雑な問題には、役割分担したサブエージェントを使用：
- 事実確認者
- シニアエンジニア
- セキュリティ専門家
- 一貫性チェッカー
- 冗長性チェッカー
