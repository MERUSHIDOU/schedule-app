# /implement スキル

## 概要

このスキルは実装タスクを新しいworktreeで開始します。複雑さを自動判断し、適切なプロンプトを生成して新セッションに委譲します。

## 使用方法

```
/implement [実装したい機能の説明]
```

## 実行内容

### 1. ブランチ名の決定

実装内容から適切なブランチ名を生成します：

- **feat/** - 新機能（デフォルト）
- **fix/** - バグ修正
- **docs/** - ドキュメント
- **refactor/** - リファクタリング
- **test/** - テスト追加
- **chore/** - 設定・ビルド

### 2. 複雑さの判断

以下の基準で自動判断します：

**複雑（/plan付きで委譲）:**
- キーワード検出: システム、アーキテクチャ、大規模、リファクタリング、設計、認証、データベース、API、移行、セキュリティ、パフォーマンス、キャッシュ、インフラ
- 複数コンポーネントにまたがる変更
- 新しいアーキテクチャパターンの導入
- 推定ファイル数が10以上

**シンプル（直接委譲）:**
- 単一コンポーネントの変更
- UIの軽微な修正
- バグ修正
- ドキュメント更新
- テスト追加

### 3. worktree作成とプロンプト送信

```bash
npm run worktree:new -- <type> <name> --prompt "<プロンプト>"
```

**シンプルな場合のプロンプト:**
```
[実装内容の説明]
```

**複雑な場合のプロンプト:**
```
/plan [実装内容の説明]
```

### 4. メインClaudeの終了

タスクを新セッションに委譲後、メインClaudeは作業を終了します。
メインのタスク完了！

## 使用例

### シンプルな機能

**入力:**
```
/implement ログアウトボタンを追加
```

**メインClaudeの動作:**
1. ブランチ名を決定: `feat/logout-button`
2. 複雑さを判断: シンプル
3. コマンド実行: `npm run worktree:new -- feat logout-button --prompt "ログアウトボタンを追加"`
4. 「タスクを新しいセッションに委譲しました」と表示
5. 終了

**新セッションのClaude:**
- プロンプト「ログアウトボタンを追加」を受け取る
- `/tdd`で実装開始
- `/code-review`でレビュー
- `/ship`でPR作成

### 複雑な機能

**入力:**
```
/implement ユーザー認証システムを追加
```

**メインClaudeの動作:**
1. ブランチ名を決定: `feat/user-auth-system`
2. 複雑さを判断: 複雑（「認証」「システム」キーワード検出）
3. コマンド実行: `npm run worktree:new -- feat user-auth-system --prompt "/plan ユーザー認証システムを追加"`
4. 「タスクを新しいセッションに委譲しました」と表示
5. 終了

**新セッションのClaude:**
- プロンプト「/plan ユーザー認証システムを追加」を受け取る
- `/plan`で計画策定
- ユーザーの承認を得る
- `/tdd`で実装
- `/code-review`でレビュー
- 必要に応じて`/security-review`
- `/ship`でPR作成

### バグ修正

**入力:**
```
/implement ログインページのボタンが表示されないバグを修正
```

**メインClaudeの動作:**
1. ブランチ名を決定: `fix/login-page-button-bug`
2. 複雑さを判断: シンプル
3. コマンド実行: `npm run worktree:new -- fix login-page-button-bug --prompt "ログインページのボタンが表示されないバグを修正"`
4. 「タスクを新しいセッションに委譲しました」と表示
5. 終了

### ドキュメント更新

**入力:**
```
/implement READMEを更新してインストール手順を追加
```

**メインClaudeの動作:**
1. ブランチ名を決定: `docs/readme-install-steps`
2. 複雑さを判断: シンプル
3. コマンド実行: `npm run worktree:new -- docs readme-install-steps --prompt "READMEを更新してインストール手順を追加"`
4. 「タスクを新しいセッションに委譲しました」と表示
5. 終了

## 委譲後の新セッション

新セッションのClaudeは以下を自動的に実行します：

1. プロンプトを受け取る
2. **シンプルな場合**: 直接`/tdd`で実装開始
3. **複雑な場合**: `/plan`で計画策定 → 承認後に`/tdd`で実装
4. `/code-review`でコードレビュー
5. セキュリティ関連の変更の場合: `/security-review`
6. `/ship`でPR作成

**重要**: 純正のtask機能を使用するため、チェックリストmdファイルは不要です。

## 技術的な詳細

### 複雑さ判断のロジック

以下のキーワードが含まれる場合、複雑と判断されます：

- 日本語: システム、アーキテクチャ、大規模、リファクタリング、設計、認証、データベース、API、移行、セキュリティ、パフォーマンス、キャッシュ、インフラ
- 英語: system, architecture, large-scale, refactor, design, auth, authentication, database, db, API, api, migration, security, performance, cache, infrastructure

### ブランチ名生成のロジック

1. キーワード検出でブランチタイプを決定
2. 不要な単語を削除（「を追加」「を実装」「を修正」「機能」「システム」「ページ」等）
3. ケバブケース（kebab-case）に変換
4. 30文字以内に制限

### プロンプト送信の仕組み

`--prompt`オプションにより、プロンプトを直接新セッションのClaudeに送信します。従来の`worktree-context.md`ファイルは使用しません。

## 注意事項

- **tmuxセッション内で実行推奨**: tmux外では自動的な新pane作成が行われません
- **メインClaudeは自動終了**: タスク委譲後、メインClaudeは作業を終了します
- **純正task機能を使用**: チェックリストmdファイルは不要です

## トラブルシューティング

### worktree作成に失敗する

- ブランチが既に存在する場合: 既存ブランチを削除するか、別の名前を使用
- ディレクトリが既に存在する場合: `npm run worktree:remove`で削除

### プロンプトが送信されない

- tmuxセッション外で実行している場合: 手動でworktreeディレクトリに移動してClaudeを起動
- Claudeの起動に時間がかかる場合: スクリプト内の`sleep`時間を調整

### 複雑さ判断が不正確

- 手動で`/plan`を指定したい場合: 直接`npm run worktree:new`コマンドを使用
- フィードバックを提供: 判断ロジックの改善に活用
